VERSION 0.5.115
Base: 0.5.114
Changes: Add program-level runtime settings and direct simulation-speed controls without putting device policy into the planet seed.
  - new settings button sits immediately left of the hamburger/menu button; on phones it follows the same top-center layout and on portrait tablets it follows the lifted bottom-right controls
  - new speed cluster sits beside Pause with slower / current multiplier / faster controls; supported rates are x0.25, x0.5, x1, x2 and x4, with the center badge resetting to x1
  - visual simulation time is now a continuous synthetic clock: planet rotation, cloud motion, storms and other uTime effects change speed every frame without introducing tick stepping; camera orbit/zoom inertia stays real-time
  - Weather Core model time per physical tick is user-selectable from 30 s, 1, 2, 3 or 5 simulated minutes; the upper bound remains the proven 300 s integration step
  - speed multiplier changes requested Weather Core cadence between 4 s and 250 ms, but cooperative scheduling still skips delayed work instead of replaying catch-up ticks
  - performance panel adds Auto / Quality / Balanced / Performance / Custom profiles, target FPS, adaptive-resolution toggle, render-scale min/max, Weather Core grid override (Auto/24/28/32/36 per cube face), and interaction-priority weather deferral
  - settings persist in localStorage for this browser/device and do not enter the world hash/seed; changing the Weather Core grid recreates the physical grid on the next tick
  - diagnostics expose current renderScale, frame-rate EMA, active Weather Core grid, Weather tick cost, deviceMemory and WebGL version while the settings panel is open
Regression: runtime settings are built between base render and per-frame weather bridges so GPU target blending keeps real wall time while shader simulation receives scaled model time; all final policy hooks install after smooth-motion/pause wrappers.
Snapshot: 0.5.114 remains the rollback point before user-configurable runtime time/performance controls.
Release rule: every new archive increments patch version by 0.0.1 and is named madPlanet-X.Y.Z.zip.
