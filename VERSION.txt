VERSION 0.5.54
Base: 0.5.53
Changes: Weather Core cloud visuals v1 - the physical cubed-sphere weather grid now owns where visible low, middle and high clouds exist. A compact RGBA8 cubemap mirrors the existing 6xNxN Weather Core only after core creation or the fixed one-second weather tick: R/G/B encode monotonic optical proxies of cloudLowMass/cloudMidMass/cloudHighMass and A carries deepConvectiveState. Desktop 48x48x6 uploads about 55 kB per weather update; no cloud-grid upload runs from requestAnimationFrame. The cubemap uses the canonical weatherFaceDir layout with one vertical row flip per OpenGL cube face and is sampled in body-fixed uRotS coordinates, so physical clouds rotate with the planet while their fine morphology can still drift. Legacy clouds.glsl entry points are macro-retired under private names; replacement lowCover/midCover/lowDeck/midDeck/highDeck/volumeLow functions take geography only from uWeatherCloudTex. Existing procedural fbm/noise/cumulus helpers now only roughen edges and internal texture inside non-zero physical condensate and cannot seed clouds in clear Weather Core cells. main.glsl no longer evaluates procedural synoptic(), weather() or lowCloudClimate() to place clouds, removing the old per-pixel terrain/climate cloud-geography pass. Deep-convective state controls low-cloud tower character and strengthens high anvils. Existing low/mid/high controls remain modest manual/visual gain and on/off controls, but no longer provide spatial morphology. Legacy clouds.glsl is deliberately left structurally intact behind renamed dead entry points to avoid risky large-file surgery; a later cleanup can delete those dead helpers after visual validation.
Roadmap note: the next physical-weather visual milestone is cloud shadows plus radiative feedback, now 0.5.55 after the inserted 0.5.53 capture/export workflow.
Release rule: every new archive increments patch version by 0.0.1 and is named madPlanet-X.Y.Z.zip.
