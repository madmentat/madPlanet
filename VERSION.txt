VERSION 0.5.141
Base: 0.5.140
Changes: Rework visible river detail into a denser basin-constrained dendritic network without giving decorative code authority over physical drainage.
  - upgrade river-visual-tributaries to model 2: lower the coarse-grid headwater threshold, select wet/slope-supported local source maxima instead of blanking an entire neighbouring Weather Core cell around every chosen source, and allow longer receiver-distance headwaters
  - add a second feeder pass along confirmed physical trunks: short side tributaries are traced upstream through wetter/higher cells, locked to the same physical basin, then reversed so the displayed branch always flows downhill into a diagnosed channel/lake receiver
  - increase sub-cell lateral displacement for feeder branches so the visible network no longer runs primarily through the centres of huge synoptic cells
  - strengthen fine tributary display amplitudes while keeping physical trunk/lake rasterization authoritative at confluences
  - rebuild display-only river topology every 12 Weather Core ticks instead of every 6, preserving the 0.5.140 frame-pacing improvement at x4 simulation speed
  - wrap the legacy shadeSurface output with a cheap physical-river visibility pass: an already diagnosed river cubemap line can no longer disappear solely because the historical procedural FBM width/climate gates reject the same pixel
  - the visibility pass preserves the existing lit surface colour and only darkens/tints diagnosed river pixels; frozen/thermally invalid surface water is not deliberately created by this display layer
Regression: extend river-visual-tributaries.test.js with reverse feeder routing, dry-basin rejection, basin/downhill invariants and the physical river surface-visibility wrapper.
