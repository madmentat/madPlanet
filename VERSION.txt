VERSION 0.5.53
Base: 0.5.52
Changes: planet capture/export workflow v1 - Screenshot now opens a compact mode chooser with an optional styled astronomical planet card and a true lightning Trigger mode. Trigger mode has no timeout: it arms until cancelled or the next visible physical lightning rising edge. screenshot-trigger.js mirrors the exact 0.5.52 GLSL flash phase/rate equations, rejects far-side storms, and re-renders the high-resolution frame with the identical requestAnimationFrame timestamp that crossed the trigger threshold, so the captured PNG contains the bolt that caused the trigger. The planet card reuses existing physical diagnostics for diameter/radius, mass, density, gravity, escape velocity, stellar class/luminosity, orbital distance/HZ status, mean temperature, surface pressure, dominant atmospheric gases, climate summary and ring material. A new Save button asks for a planet name and downloads a local .madplanet.json archive containing primitive user state, summary and canonical share URL; no localStorage, IndexedDB, account or server database is introduced. Planet names are metadata carried in the named URL hash as name=<encoded> and restored from shared links. A new Share button uses Web Share with a synchronous card-PNG capture while transient user activation is live, including the PNG as a File where supported; fallback actions provide copy-link, mailto and PNG download. The existing URL hash remains the authoritative mechanism for opening/reproducing planets; JSON import is intentionally not added in this milestone.
Roadmap note: the previously planned Weather Core cloud-visual coupling moves to the next patch after this user-workflow milestone; its physics prerequisites are unchanged.
Release rule: every new archive increments patch version by 0.0.1 and is named madPlanet-X.Y.Z.zip.
